Запусти агента `developer` через Agent tool (subagent_type: "developer") на один проход.

Ниже, в `$ARGUMENTS`, передан идентификатор Linear-тикета (например `dif-123`).
Developer сам прочитает план из Linear-комментария `## Agent Workpad` этого
тикета и сам определит, первый это раунд или повторный, по фактическому
состоянию git-ветки `ai/<issue-identifier>` и её PR — никакого файла со
статусом для этого нет и не нужно.

В обоих случаях Developer сам коммитит, пушит ветку и создаёт/обновляет pull
request; это не твоя ответственность и не ответственность отдельного
review-агента — его в этом пайплайне нет.

Результат:
- `NO_PLAN` — план ещё не записан в `## Agent Workpad`; сообщи и останови цикл.
- `BLOCKED` / `STALE_PLAN` — сообщи причину и останови цикл.
- `PUSHED` — ветка закоммичена, запушена, PR создан или обновлён, раунд
  дописан в Linear. Готово.

По завершении выведи в консоль итог: issue identifier, ветка, PR-ссылка,
изменённые файлы.

Вход (идентификатор Linear-тикета):
$ARGUMENTS
